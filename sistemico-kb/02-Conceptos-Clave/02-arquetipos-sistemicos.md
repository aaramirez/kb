# Arquetipos Sistémicos

Los arquetipos sistémicos son **patrones de comportamiento** que se repiten en innumerables situaciones, desde ecosistemas hasta organizaciones. Identificarlos permite diagnosticar problemas estructurales en lugar de tratar síntomas.

> "Los arquetipos sistémicos revelan la elegante simplicidad que subyace a la complejidad de los problemas de gestión." — Peter Senge

## Principales Arquetipos

### 1. Límites del Crecimiento
**Patrón**: Un bucle reforzador acelera el crecimiento hasta que un balanceador lo frena.

```
  Crecimiento (R) → encuentra → Límite (B) → frena crecimiento
```

**Ejemplo**: Una startup crece rápido hasta que choca con la falta de procesos o cultura.
**Intervención**: No empujes el crecimiento; elimina o modifica el factor limitante.

### 2. Desplazamiento de la Carga (Shifting the Burden)
**Patrón**: Se aplica una solución rápida (sintomática) que alivia el síntoma pero evita resolver la causa raíz, debilitando la capacidad del sistema para solucionar el problema real.

```
  Síntoma → Solución rápida → Alivio temporal → No se resuelve causa raíz → Síntoma vuelve
```

**Ejemplo**: Micro-management para cubrir falta de competencias → equipo no desarrolla autonomía.
**Intervención**: Fortalecer la capacidad fundamental, no depender de soluciones sintomáticas.

### 3. Éxito para los Exitosos
**Patrón**: Dos actividades compiten por recursos limitados. La que tiene más éxito recibe más recursos, lo que aumenta su éxito y priva a la otra.

```
  Actividad A → (+) → Recursos → (−) → Actividad B
```

**Ejemplo**: Un producto estrella absorbe todo el presupuesto de I+D, nuevos productos nunca despegan.
**Intervención**: Romper el vínculo o crear mecanismos de protección para actividades emergentes.

### 4. Tragedia del Común
**Patrón**: Un recurso compartido se degrada porque cada individuo actúa en su interés propio.

```
  Uso individual (+) → Beneficio individual → (+) → Más uso → (−) → Recurso compartido
```

**Ejemplo**: Tiempo en reuniones: cada líder convoca sin considerar el tiempo colectivo.
**Intervención**: Educación, regulación del común, diseñar incentivos alineados.

### 5. Escalada
**Patrón**: Dos partes compiten donde cada una responde a la amenaza de la otra, escalando el conflicto.

```
  Acción de A → (+) → Amenaza para B → (+) → Acción de B → (+) → Amenaza para A
```

**Ejemplo**: Guerra de precios entre competidores.
**Intervención**: Desescalada unilateral, encontrar objetivo común, cambiar las reglas.

### 6. Fijación de Metas que se Desplazan
**Patrón**: La brecha entre la meta y la realidad se cierra bajando la meta, no mejorando la realidad.

**Ejemplo**: Equipo de ventas reduce cuotas en lugar de mejorar desempeño.
**Intervención**: Mantener metas firmes, invertir en capacidad real.

### 7. Soluciones Rápidas que Fracasan
**Patrón**: Una solución rápida alivia el síntoma temporalmente, pero genera efectos secundarios que empeoran el problema original.

**Ejemplo**: Deuda técnica: código rápido hoy → más difícil de mantener mañana → más código rápido.
**Intervención**: Pagar la deuda antes de que los intereses la vuelvan impagable.

### 8. Crecimiento y Subinversión
**Patrón**: La demanda crece pero no se invierte en capacidad, lo que limita el crecimiento y desalienta más inversión.

**Ejemplo**: Sistema que crece en usuarios pero no en infraestructura → experiencia degradada → menos crecimiento.
**Intervención**: Inversión agresiva en capacidad como prioridad estratégica.

## Cómo Usarlos

1. **Identificar** el patrón: preguntar "¿esto me suena a algún arquetipo?"
2. **Diagnosticar**: mapear las variables y bucles del arquetipo
3. **Intervenir**: la solución estructural está en cambiar la configuración del sistema, no en tratar el síntoma

## Conexión con IA

Los arquetipos son directamente aplicables a sistemas de IA:

| Arquetipo | Ejemplo en IA |
|-----------|---------------|
| **Límites del crecimiento** | Modelo que mejora hasta que choca con calidad de datos |
| **Desplazamiento de la carga** | Usar modelos pre-entrenados (solución sintomática) sin construir datos propios |
| **Éxito para los exitosos** | Un modelo recibe más datos porque es el más usado, otros nunca maduran |
| **Escalada** | Carrera de prompts adversariales entre atacante y defensor |
| **Soluciones rápidas** | Fine-tuning sin considerar alineamiento → comportamientos no deseados |
